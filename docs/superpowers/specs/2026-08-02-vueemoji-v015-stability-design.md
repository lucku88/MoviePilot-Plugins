# Vue-表情 v0.1.5 稳定性与页面细节设计

## 目标

在不改变现有配置、历史记录和游戏功能的前提下，消除 Vue-表情重复方法、双层网络重试和不可逆操作超时后重复提交的风险，同时统一舞台剩余时间并微调桌面与手机页面。

## 已确认问题

1. `VueEmoji` 类中 `_run_auto_spin` 和 `_manual_spin` 各定义两次，文件前面的实现会被后面的实现静默覆盖，维护时容易修错代码。
2. `_build_session()` 使用 urllib3 自动重试，外层 `_request_with_retry()` 又手动重试，GET 请求可能超过插件配置的 5 次总上限。
3. `spin_slot`、`open_bag`、`accept_open`、`reroll_open`、`upgrade_bag`、`expand_stage_row`、`confirm_stage_cast`、`recall_stage` 都会改变站点状态。响应超时时直接重发可能重复扣次数、扣魔力或重复开启内容。
4. 舞台状态同时使用后端 `remaining_seconds` 和由 `remaining_end_ts` 计算的倒计时，站点时间字段不一致时会在同一卡片显示两个不同剩余时间。

## 后端设计

### 单层网络重试

- requests/urllib3 适配器保留安装，但 `total`、`connect`、`read` 都设为 `0`。
- 所有安全 GET 请求只由 `_request_with_retry()` 控制，总尝试次数最多为配置值，默认 5 次。
- 非网络错误和明确的业务拒绝不重试。

### 不可逆操作确认

- `_post_action()` 只负责发起一次 POST，不在内部盲目重试。
- 新增动作状态标记与确认流程。POST 遇到可重试网络错误时，先重新读取完整页面状态。
- 如果状态已经发生该动作对应的变化，返回“已确认成功”的合成结果，不再次 POST。
- 如果状态完整且明确未变化，才允许下一次 POST；总 POST 尝试不超过 5 次。
- 如果状态无法读取或变化无法判断，立即停止当前动作，由现有错误调度短期刷新，避免重复消费。

动作确认依据：

- 老司机老虎机：已用次数增加或表情包库存增加。
- 开包：目标表情包库存减少或出现新的待处理开包结果。
- 收下：原待处理结果消失。
- 重开：待处理结果的重开次数、消耗或结果签名变化。
- 合成：相关表情包库存发生变化。
- 扩展舞台：目标行已开放格子数量增加。
- 确认演出：舞台由无演出变为有演出。
- 收回演出：舞台由有演出变为无演出；奖励用前后用户数值差补齐。

### 重复代码清理

- 保留文件后部带老虎机状态恢复的实现，并移动到原自动流程区域。
- 删除被 Python 覆盖的旧实现，确保每个类方法只定义一次。
- 修正手动老虎机成功后误用舞台状态确认函数的问题，改为读取动作返回状态或刷新页面。

## 页面设计

- 保留 v0.1.4 的 MoviePilot 深浅主题、自适应卡片和全部操作入口。
- 舞台状态只显示一个可信倒计时：优先使用后端 `remaining_seconds` 对应文字，字段缺失时再用结束时间计算。
- 开包与老虎机数字输入框文字垂直、水平居中，按钮和输入框统一高度。
- 禁用按钮仍保留原因文字，手机端操作区自动换行且不产生横向滚动。
- 不新增配置项，不删除 `force_ipv4` 等现有配置，本次仅处理已批准范围。

## 测试策略

- 新增 `tests/test_vueemoji_backend.py`，使用 MoviePilot 桩加载真实插件类。
- 用 AST 断言类方法没有重复定义。
- 断言 HTTPAdapter 不进行第二层重试，外层网络调用最多 5 次。
- 对每种不可逆动作至少覆盖共同确认框架，并重点覆盖老虎机、开包、舞台的超时已成功和确认未变化后重试。
- 前端契约测试增加舞台单一倒计时、输入框对齐和手机布局断言。
- 运行生产构建、后端编译、Vue-表情测试、自动补跑测试和重试上限测试。

## 发布与升级

- 版本升级为 `0.1.5`。
- 同步后端、npm 包、市场索引和 README。
- 小版本升级保留配置、历史和动态调度数据，不要求重置插件。
- 推送 `main` 后自动刷新 MoviePilot 插件市场并更新已安装插件，只执行刷新、读取状态和页面验证，不主动消耗游戏资源。
