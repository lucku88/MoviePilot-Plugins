# Vue-魔丸任务优先状态页设计

## 背景

Vue-魔丸 `v0.2.6` 已具备搬砖、清理沙滩、兑换魔力、查看物品、赠送、炼造和执行历史等完整功能。当前状态页的主要问题不是功能缺失，而是信息密度和先后顺序不够合理：

- 搬砖和沙滩使用上下长条，在电脑端没有充分利用横向空间。
- 物品栏与炼造工坊左右并排后，两边都变成很长的单列，页面长度和浏览压力较大。
- 可赠送与不可赠送物品使用相近的大卡片，不可操作信息占用了较多空间。
- 状态接口已经返回下一次触发时间和动作，但页面没有把这些自动运行信息放在显眼位置。

本设计采用已确认的 **方案 A：任务优先工作台**。插件最先回答“自动任务是否正常、下一项是什么、什么时候运行”，再提供兑换、赠送和炼造等手动操作。

## 目标

- 保持 Vue-农场、Vue-玩偶和 Vue-表情现有的自适应视觉语言，不固定为浅色或深色。
- 第一屏优先展示自动运行状态、搬砖、沙滩和兑换。
- 将物品栏改为全宽紧凑网格，将炼造工坊改为全宽配方网格。
- 电脑端提高横向空间利用率，手机端不出现横向滚动或内容挤压。
- 保留现有刷新、配置、兑换、赠送、赠送统计、炼造、一键炼造和历史功能。

## 非目标

- 不修改搬砖、沙滩、兑换、赠送或炼造的后端规则。
- 不调整动态调度、网络重试、Cookie 同步和通知逻辑。
- 不增加新的配置项。
- 不复刻游戏网站的固定浅色样式，仅借鉴其内容分区和物品格表达方式。

## 页面结构

状态页从上到下固定为以下顺序：

1. 顶部栏：插件名称、说明、自动运行摘要、刷新、配置和关闭。
2. 四项概览：魔力、已兑换魔力、当前魔丸数、今日搬砖。
3. 第一操作区：左侧自动任务，右侧兑换魔力。
4. 物品栏：全宽紧凑物品网格。
5. 炼造工坊：全宽配方网格。
6. 执行历史：保持单行内容和右对齐时间。

### 顶部自动运行摘要

顶部栏增加一条低干扰摘要，例如：`自动运行正常 · 下一项：沙滩 11:26`。数据直接使用现有 `/status` 返回的 `enabled`、`next_trigger_time` 和 `next_trigger_action`，不增加后端接口。

- 插件启用且存在计划时显示绿色正常状态。
- 插件未启用时显示中性“自动运行未启用”。
- 暂时没有计划时间时显示“等待识别下一次任务”，不显示错误色。
- 手机端隐藏长摘要，只保留现有操作图标，避免标题被挤压。

### 概览卡

继续使用四列概览，颜色只用于图标、数值和左侧细线。卡片主体使用 MoviePilot 当前主题的表面颜色，减少整张彩色背景带来的突兀感。

- 电脑端：四列。
- 手机端：两列。
- 数值使用等宽数字表现，避免刷新时宽度明显跳动。

### 自动任务与兑换

电脑端保持“任务较宽、兑换较窄”的两栏结构。自动任务内部将搬砖和沙滩改成并排双卡：

- 搬砖卡显示今日数量、上限、可搬数量和重置时间。
- 沙滩卡显示等级、HNR、剩余或可用时间。
- 状态使用小标签表达“可以搬砖”“今日完成”“冷却中”“可以清理”。
- 按钮沿用现有启用条件和加载状态，不改变是否允许执行的判断。
- 不伪造精确百分比；只有后端数据能够计算进度时才显示进度条，否则使用状态分隔线。

兑换区保留当前魔丸、单颗价值和最大可兑换数量。最大可兑换数量直接显示 `exchange.max_count`，文案改为“最多兑换”，避免重复强调“后端上限”。保留魔丸提示保持简短，并继续以后端校验结果为准。

### 物品栏

物品栏改为全宽网格，按后端返回顺序展示，不改变物品数据和赠送规则。

- 宽屏每行最多 7 个，中等宽度每行 4 至 5 个，手机每行 3 个。
- 每格显示图标、名称和数量。
- 可赠送物品显示低强调“赠送”入口，点击后继续打开现有确认弹窗。
- 不可赠送物品不再反复显示“不可赠送”，只使用无按钮状态表达。
- 炼造产物使用轻微的同色背景区分，但仍适配 MoviePilot 当前主题。
- “赠送统计”继续放在区块标题右侧。

### 炼造工坊

炼造工坊单独全宽显示：

- 宽屏三列，中等宽度两列，手机单列。
- 每张卡显示产物、当前最多可炼造数量、材料拥有量/需求量、数量输入框和炼造按钮。
- 材料充足使用轻微成功色，材料不足使用普通中性色或低强调警示色，不重复显示大段“材料不足”。
- 数量输入、禁用条件、错误提示和请求防重复逻辑完全沿用现有实现。
- “一键炼造魔丸”继续放在区块标题右侧。

### 执行历史

历史继续使用一行记录：左侧操作结果，右侧时间。内容过长时左侧省略，时间始终完整显示；手机端仍保持时间靠右，不拆成独立大卡片。

## 数据与组件边界

后端 `/status` 已提供所需数据，不修改 API。前端状态容器除 `pill_status` 和 `history` 外，需要保留以下根级字段：

- `enabled`
- `next_run_time`
- `next_trigger_time`
- `next_trigger_action`

状态载入和操作完成后的状态回填必须统一经过同一个解析函数，防止手动刷新、兑换、赠送或炼造后顶部摘要显示旧时间。现有请求序号保护、错误提示和操作锁继续保留。

## 加载、空状态与错误

- 首次加载继续显示骨架屏，骨架结构与最终网格一致，避免页面明显跳动。
- 物品或配方为空时继续显示区块内空状态，不隐藏整个区块。
- 状态请求失败时保留上一次成功数据，并使用现有顶部消息提示失败原因。
- 单个手动操作失败时只恢复对应按钮，不清空其他区块。
- 自动运行摘要没有时间时显示等待识别，不把正常缺少计划误报为故障。

## 主题与响应式

所有背景、文字和边框继续使用 Vuetify 的 `--v-theme-*` 变量。绿色、青色、橙色等只作为小面积强调色，不使用固定大面积深色卡片。

响应式断点：

- `> 1100px`：任务与兑换双栏，任务内部双卡，物品 7 列，配方 3 列。
- `701px - 1100px`：任务与兑换上下排列，物品 4 至 5 列，配方 2 列。
- `<= 700px`：概览 2 列、任务单列、物品 3 列、配方单列。

任何宽度下都不允许页面产生横向滚动。

## 实施范围

主要修改：

- `plugins.v2/vuepill/src/components/Page.vue`
- 必要时小幅扩展 `plugins.v2/vuepill/src/utils/asyncGuards.js` 的状态字段提取结果，并补充对应前端测试。
- 重新构建 `plugins.v2/vuepill/dist`。
- 发布版本计划升级为 `v0.2.7`，同步后端版本、`package.json`、`package-lock.json`、根市场索引和 README 更新说明。

不修改 `plugins.v2/vuepill/__init__.py` 的业务执行路径；仅允许同步版本元数据。

## 验收标准

- 电脑端第一屏能同时看到四项概览、搬砖、沙滩和兑换。
- 物品栏不再出现左右半屏的超长单列，14 个物品能以紧凑网格显示。
- 六个炼造配方在宽屏稳定显示为三列。
- 浅色、深色及 MoviePilot 其他主题下文字和边框均清晰。
- `390 × 844` 手机尺寸无横向滚动，按钮、数量和时间不重叠。
- 刷新、配置、兑换、赠送、赠送统计、单项炼造、一键炼造和历史展示行为保持正常。
- `next_trigger_action` 和 `next_trigger_time` 更新后，顶部自动运行摘要同步更新。
- 前端构建成功，已有 Vue-魔丸后端测试和前端测试不回归。
