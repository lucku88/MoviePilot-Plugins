# Vue-魔丸 v0.2.0 重写设计

## 1. 背景

Vue-魔丸当前版本为 `v0.1.18`。现有插件已经具备搬砖、沙滩清理、炼造、兑换、动态调度和异常重试能力，但页面仍使用早期独立样式，后端也存在重复函数和页面解析不稳定的问题。

本次升级以 Vue-农场为页面模板，重写 Vue-魔丸 `v0.2.0`。新版保留成熟的动态调度边界，完整接入游戏页面的物品、配方、赠送和赠礼统计功能，并把后端整理为职责清晰、可测试的实现。

设计已确认采用以下决策：

- 页面采用「方案 A：Vue-农场同款完整移植」。
- 升级到 `v0.2.0` 时使用全新默认配置，并清空旧调度和旧执行历史。
- 站点 Cookie 固定从 MoviePilot 站点管理自动同步，不再提供 Cookie 开关或输入框。
- 新增手动赠送、赠礼统计和收礼统计，但不提供自动赠送。
- 默认使用安全模式：插件关闭，搬砖与动态沙滩预设开启，自动炼造与自动兑换关闭，保留魔丸数量为 `10`。

## 2. 目标

### 2.1 用户目标

- 页面结构、操作方式和主题适配与 Vue-农场保持一致。
- 在一个状态页中完成搬砖、沙滩清理、物品查看、六种配方炼造、魔丸兑换和赠礼操作。
- 沙滩继续按真实冷却时间动态运行，不使用固定周期。
- 搬砖继续使用独立 Cron，不影响沙滩调度。
- 自动兑换始终保留配置数量的魔丸。
- 自动和手动执行使用统一的一行历史格式，时间靠右显示。

### 2.2 工程目标

- 删除重复定义的搬砖、通知和历史函数，保证每项行为只有一份实现。
- 以真实页面数据为准解析物品和配方，避免固定 HTML 结构变化后全部失效。
- 对页面状态不确定的情况采用保守策略，不提前执行会改变账号数据的操作。
- 为页面解析、调度、兑换保留、赠送和升级重置增加回归测试。

## 3. 非目标

- 不实现自动赠送。
- 不开放游戏的重置进度接口。
- 不开放管理员专用的游戏间隔设置。
- 不修改网站规则、掉落概率或炼造配方。
- 不使用固定周期替代沙滩真实冷却时间。

## 4. 稳定版本备份

开始修改插件代码前，为当前 `v0.1.18` 创建并推送稳定标签：

```text
vuepill-v0.1.18-stable
```

标签指向重写前的 `main`，用于快速查看或恢复旧版代码。标签只做备份，不改变当前分支。

## 5. 页面设计

### 5.1 状态页

状态页沿用 Vue-农场的顶部工具栏、卡片层次、输入控件、移动端布局和主题变量。

页面按以下顺序显示：

1. **顶部工具栏**
   - 标题：`Vue-魔丸 · 状态`
   - 副标题：搬砖、沙滩、炼造与魔力兑换
   - 操作：立即执行、刷新、配置、关闭
   - 不显示同步 Cookie 按钮

2. **概览卡片**
   - 当前魔力
   - 已兑换魔力
   - 当前魔丸
   - 今日搬砖进度

3. **自动任务区**
   - 搬砖卡：今日进度、工坊可搬数量、口袋砖块数量、下次重置时间、立即搬砖按钮
   - 沙滩卡：真实冷却倒计时、发种等级、HNR 值、魔丸掉落提示、清理并收集按钮
   - 卡片顶部显示下一次任务类型和计划时间

4. **魔丸中心**
   - 一键炼造魔丸：输入数量、最大可炼造数量、完整材料链提示
   - 兑换魔力：动态价格、输入数量、当前可兑换数量、保留魔丸提示

5. **物品栏**
   - 显示全部 14 种物品和当前数量
   - 有库存的基础物品高亮，无库存的炼造物品弱化
   - 只有网站允许赠送的基础物品和蚯蚓显示「赠送」按钮
   - 区块顶部提供「赠礼记录」和「收礼记录」按钮

6. **炼造工坊**
   - 显示六种真实配方
   - 每张卡显示当前数量、所需数量、最大可制作数量、数量输入和炼造按钮
   - 材料不足时禁用按钮，并明确显示缺少的材料

7. **执行历史**
   - 自动和手动操作统一为一行内容
   - 时间在同一行靠右
   - 不显示「任务结果」等额外标题

### 5.2 配置页

配置页沿用 Vue-农场的顶部栏、开关卡片、参数网格和 Cron 输入组件。

#### 基础设置

- 启用插件：默认关闭
- 开启通知：默认开启
- 立即运行一次：默认关闭
- 使用代理：默认关闭
- 强制 IPv4：默认开启
- Cookie 来源只显示自动同步结果，不提供开关和输入框

#### 自动化策略

- 自动搬砖：默认开启
- 动态清沙滩：默认开启
- 自动炼造魔丸：默认关闭
- 自动兑换魔力：默认关闭

#### 参数设置

- 搬砖执行时间：Cron，默认 `5 0 * * *`
- 冷却完成缓冲：默认 `5` 秒
- 保留魔丸数量：默认 `10`
- 随机延迟上限：默认 `5` 秒
- 请求超时：默认 `12` 秒
- 网络重试次数：默认 `5` 次，最大 `5` 次
- 网络重试间隔：沿用现有毫秒配置并在页面显示为秒
- 沙滩临界状态短重试：保留现有内部默认值，不增加普通用户不需要的开关

### 5.3 手动赠送

点击可赠送物品后打开确认弹窗，包含：

- 物品名称
- 当前库存
- 目标用户 UID
- 赠送数量
- 最大可赠送数量

最大可赠送数量取 `min(当前库存, 500)`。提交前必须二次确认。成功后刷新物品栏并写入一条手动历史；失败时显示网站返回原因。

插件不保存赠送目标，不提供批量赠送或自动赠送。

### 5.4 赠礼与收礼统计

统计弹窗支持：

- 最近 30 天
- 全部记录
- 总事件数
- 总数量
- 用户汇总
- 物品汇总

按钮文案继续使用「赠礼记录」「收礼记录」，弹窗标题使用「赠礼统计」「收礼统计」。统计接口为只读操作，不写入插件执行历史。

## 6. 游戏接口

插件只接入以下游戏动作：

| 动作 | 网站 action | 用途 | 是否改变账号数据 |
| --- | --- | --- | --- |
| 同步状态 | `sync_game_state` | 读取搬砖与服务器时间 | 否 |
| 搬砖 | `move_brick` | 搬取当天剩余砖块 | 是 |
| 进入沙滩 | `enter_beach` | 生成本轮垃圾 | 是 |
| 一键收集 | `collect_all_trash` | 收集当前沙滩全部垃圾 | 是 |
| 炼造 | `craft_item` | 按配方和数量炼造 | 是 |
| 兑换魔力 | `exchange_points` | 魔丸兑换魔力 | 是 |
| 赠送物品 | `gift_item` | 向指定 UID 赠送物品 | 是 |
| 赠礼统计 | `gift_stats` | 查询赠礼或收礼汇总 | 否 |

不接入 `reset_game` 和 `update_settings`。

## 7. 页面解析

### 7.1 数据来源优先级

页面解析按以下优先级读取数据：

1. 页面脚本中的 `gameData`、真实配方 JSON 和服务器时间戳
2. 页面元素的数值、按钮状态和输入框限制
3. 文本文案作为最后兜底

不得仅根据「没有解析到下次时间」判断操作已经可执行。

### 7.2 搬砖

搬砖状态同时解析：

- 今日已搬数量和网站每日上限
- 工坊可搬数量
- 口袋砖块数量
- 按钮或拖拽区域是否可操作
- 服务器当前时间和下次重置时间
- 状态文案

当每日数量达到上限或操作区域被禁用时，必须判断为不可搬砖。

### 7.3 沙滩

沙滩是否可运行由以下信息共同决定：

- `lastBeachTime + beachInterval`
- 网站服务器时间
- 清理按钮是否禁用
- 状态文案是否仍包含倒计时
- 是否已经进入沙滩且存在待收集垃圾

任一关键数据矛盾时采用保守结果：先短时间刷新，不立即进入沙滩。

如果已经进入沙滩并存在待收集垃圾，即使冷却时间尚未完成，也允许继续执行一键收集。

### 7.4 配方

优先读取页面脚本中的完整配方 JSON，包括：

- `recipe_id`
- 产物名称和图标
- 单次产物数量
- 材料名称、图标和需求数量

页面卡片只用于补充最大可制作数量和按钮状态。固定配方定义只作为页面数据完全缺失时的兼容兜底。

## 8. 自动化规则

### 8.1 搬砖

- 使用独立 Cron，默认每天 `00:05`。
- 每轮按网站当天剩余额度执行，不写死为 `50`。
- 单次接口返回超时后重新读取页面，用今日搬砖数量和砖块库存差值确认是否实际成功。
- 搬砖触发不能顺带执行尚未到时间的沙滩任务。

### 8.2 沙滩

- 使用真实冷却时间动态调度。
- 冷却到点前 1 分钟进行预刷新。
- 正式触发时如果页面仍显示临界状态，短暂重抓后再判断。
- 到点窗口内变为可清理时，立即执行进入沙滩和一键收集。
- 进入成功但收集失败时，刷新页面确认是否仍有垃圾，并只重试收集阶段。
- 沙滩触发不能顺带执行未到 Cron 时间的搬砖。

### 8.3 自动炼造

- 仅在自动炼造开关开启时执行。
- 默认在沙滩收集完成后，根据当前库存计算完整魔丸材料链。
- 每种配方单次请求最多 `100` 个。
- 每一步成功后重新读取库存，再进行下一步，避免累计库存返回导致数量计算错误。
- 任一步失败时停止后续炼造，保留已经成功的产物，并记录明确原因。

### 8.4 自动兑换

- 仅在自动兑换开关开启时执行。
- 可兑换池为 `当前魔丸 - 保留魔丸数量`。
- 单次请求最多兑换 `100` 个；超过限制时分批执行。
- 每批完成后刷新库存和魔力，直到达到保留数量、网站拒绝或出现错误。
- 任何情况下不得把魔丸兑换到低于保留数量。

## 9. 调度与补跑

保留现有已经验证的调度边界：

- 保存配置后自动刷新状态；发现沙滩已可运行或旧计划确实过期时立即补跑。
- MoviePilot 重启注册插件后自动刷新；错过真实运行点时立即补跑。
- 正常预刷新不能误触发尚未到时间的正式任务。
- 搬砖 Cron 和沙滩动态时间分别注册，时间相同时才合并为整轮执行。
- 网络异常单次请求最多重试 `5` 次。
- 连续短间隔补跑最多 `5` 轮，超过后停止刷屏并回到正常计划。

## 10. v0.2.0 一次性重置

插件使用数据标记记录是否完成 `v0.2.0` 初始化。首次加载新版且标记不存在时：

1. 忽略传入的旧版功能配置。
2. 写入新版安全默认配置。
3. 清空旧执行历史、旧状态缓存、旧下次运行时间、旧触发方式和连续错误计数。
4. 不清理 MoviePilot 站点 Cookie。
5. 写入 `v0.2.0` 初始化标记，防止之后保存或重启时再次重置。

首次重置后插件保持关闭。用户打开配置页确认并保存后，才开始注册新版任务。

## 11. 后端结构

重写后按职责拆分：

- `__init__.py`：插件生命周期、MoviePilot API、配置、调度和通知
- `site_client.py`：会话、Cookie、GET 页面和 POST 动作
- `page_parser.py`：纯页面解析，不发网络请求
- `crafting.py`：库存映射、配方计算、一键炼造计划

模块之间只传递普通字典和明确参数。解析器和炼造计算可独立单元测试。

## 12. 状态与 API

对前端提供的主要接口：

- `GET /config`
- `POST /config`
- `GET /status`
- `POST /refresh`
- `POST /run`
- `POST /move-bricks`
- `POST /clean-beach`
- `POST /exchange-points`
- `POST /craft-item`
- `POST /craft-max-pill`
- `POST /gift-item`
- `POST /gift-stats`

配置和状态接口不得返回站点 Cookie、MoviePilot API 令牌或其他敏感数据。

## 13. 历史与通知

历史示例：

```text
🧱搬砖：🧱砖块×49 / 🏖️沙滩：🪵木材×3 🛍️塑料袋×2 / ⚒️炼造：⚗️魔丸×4 / 💰兑换：⚗️魔丸×4，魔力+4000    2026-07-23 13:26:50
```

手动赠送示例：

```text
🎁赠送：🪵木材×10 / 目标 UID 12345    2026-07-23 13:30:12
```

通知继续使用任务报告结构，内容只包含本轮实际成功动作和下次运行时间。无动作的普通刷新不发送通知。

## 14. 错误处理

- Cookie 同步失败：停止会改变账号数据的动作，页面显示同步失败原因。
- 页面关键数据解析失败：不猜测可执行状态，安排短刷新。
- 搬砖请求超时：刷新页面核对今日数量和砖块库存，避免重复搬砖。
- 沙滩进入成功但收集失败：只重试收集，不重复进入。
- 炼造或兑换部分成功：保留成功结果，停止后续步骤并记录剩余原因。
- 赠送失败：显示网站返回信息，不自动重试，避免重复赠送。
- 统计接口失败：只提示加载失败，不影响自动任务。

所有日志必须屏蔽 Cookie 和 MoviePilot API 令牌。

## 15. 测试计划

### 15.1 后端单元测试

- 使用脱敏后的真实页面源码作为解析测试夹具。
- 正确解析魔力、已兑换魔力、魔丸和今日搬砖。
- 正确解析工坊可搬数量和口袋砖块数量。
- 沙滩按钮禁用且有倒计时时不得判断为 ready。
- 沙滩存在待收垃圾时允许继续收集。
- 正确解析全部 14 种物品和赠送能力。
- 正确解析六种配方、配方编号、材料和最大制作数量。
- 魔丸价格和兑换上限从页面动态读取。
- 自动兑换分批执行且始终保留 `10` 个魔丸。
- 手动赠送限制为当前库存和 `500` 的较小值。
- 赠礼统计支持 `30` 天和全部范围。
- 搬砖与沙滩调度互不扩大执行范围。
- 保存、重启和预刷新补跑行为保持正确。
- 网络异常和连续短重试最多 `5` 次。
- `v0.2.0` 重置只执行一次，后续保存不会再次清空配置。

### 15.2 前端验证

- 状态页和配置页在桌面、平板和手机宽度正常显示。
- 浅色、深色以及 MoviePilot 自定义主题下文字和边框可读。
- 所有数量输入都有限制和错误提示。
- 手动赠送必须经过二次确认。
- 历史时间在同一行靠右，窄屏时允许自然换行。
- 运行 `npm run build` 并提交最新 `dist`。

### 15.3 静态与集成验证

- 运行 Python 编译检查。
- 运行 Vue-魔丸及 Vue 公共调度回归测试。
- 解析 `package.v2.json`、`package.json` 和 `package-lock.json`。
- 版本号统一为 `0.2.0`。
- 使用 MoviePilot 进行只读状态冒烟测试。
- 会改变账号数据的线上动作由用户更新插件后自行验证，不在开发过程中自动触发。

- 后端、前端包和市场索引统一升级为 `0.2.0`。
- 更新 `README.md`，说明新版页面、动态调度、赠送、赠礼统计和一次性重置行为。

- 验证通过后提交并推送 `main`。
