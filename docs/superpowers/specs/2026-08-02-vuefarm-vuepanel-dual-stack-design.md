# Vue-农场与 Vue-面板移除 IPv4 限制设计

## 1. 目标

让仓库中最后仍会强制 IPv4 的 `Vue-农场` 和 `Vue-面板` 恢复系统默认网络选择。系统可根据当前环境自动使用 IPv4 或 IPv6，不再由插件持续修改 `urllib3` 的全局地址族选择。

本次更新必须保留现有 Cookie、业务配置、执行历史和动态调度计划，不要求重置插件或重启 MoviePilot。

## 2. 当前问题

- `Vue-农场` 配置页仍显示“强制 IPv4”，后端在自动任务、状态刷新和手动操作前都会把网络限制为 IPv4。
- `Vue-面板` 虽然没有明显的 IPv4 开关，但前端配置模型、后端公开配置和请求执行仍保存并使用 `force_ipv4`。
- 热更新只删除新代码还不够：旧版本可能已经在当前 MoviePilot 进程中留下 IPv4-only 的全局选择器，需要安全地恢复系统默认行为。

## 3. 方案

### 3.1 Vue-农场

- 删除配置页的“强制 IPv4”开关、默认值和保存字段。
- 删除后端 `_force_ipv4` 状态、默认配置、公开配置和全部请求前的 IPv4 强制代码。
- 读取旧配置时忽略 `force_ipv4`，下一次保存配置后不再持久化该字段。
- 插件初始化时仅识别由旧版 `vuefarm/__init__.py` 留下的 IPv4-only 选择器并恢复系统默认选择，不修改其他插件或用户自定义的网络选择器。

### 3.2 Vue-面板

- 删除前端配置模型、归一化和保存请求中的 `force_ipv4`。
- 删除后端 `_force_ipv4` 状态、默认配置、状态接口、公开配置和请求前的 IPv4 强制代码。
- 读取旧配置时忽略该字段，保存时不再写回。
- 插件初始化时只清理由旧版 `vuepanel/__init__.py` 留下的 IPv4-only 选择器。

### 3.3 热更新边界

清理逻辑通过选择器函数的源码文件判断来源，只处理以下旧实现：

- `plugins.v2/vuefarm/__init__.py`
- `plugins.v2/vuepanel/__init__.py`

如果当前选择器来自其他插件、MoviePilot 本体或用户自定义代码，则保持不变，避免跨插件误改。

## 4. 发布与兼容

- `Vue-农场` 升级到 `v0.2.14`。
- `Vue-面板` 升级到 `v0.1.36`。
- 同步两个插件的后端版本、`package.json`、`package-lock.json`、`package.v2.json` 和 `README.md`。
- 重新构建两个插件的前端 `dist`。
- 小版本升级继续保留配置、Cookie、执行历史和调度数据；旧 `force_ipv4` 字段自动忽略。

## 5. 测试

- 先增加失败测试，锁定前端不再展示或提交 `force_ipv4`。
- 后端测试确认默认配置、公开配置和持久化数据均不含 `force_ipv4`。
- 模拟旧版 IPv4-only 选择器，确认热更新后恢复系统默认；模拟其他来源选择器，确认不会被修改。
- 运行农场与面板相关测试、全部 Vue 插件测试、Python 编译、JSON 校验、前端生产构建和 `git diff --check`。
- 发布后在 MoviePilot 中更新两个插件，确认版本、配置和历史保留，并分别刷新状态和执行一次实际请求，检查双栈改动没有影响原有功能。

## 6. 不在本次范围

- 不调整四个游戏插件的页面排列和视觉风格。
- 不修改收菜、偷菜、点赞、签到、领取或调度业务逻辑。
- 不清理历史设计文档中用于说明旧版本的 IPv4 文字。
