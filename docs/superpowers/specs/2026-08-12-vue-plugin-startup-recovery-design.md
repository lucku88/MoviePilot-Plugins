# Vue 动态插件启动恢复设计

## 背景

MoviePilot v2.15.6 启动时，会先加载插件并登记所有插件服务，最后才启动 APScheduler 调度器。

Vue-农场、Vue-魔丸、Vue-玩偶和 Vue-表情目前都通过 `date` 类型的一次性任务完成启动初始化。任务时间设置为插件初始化后的 3～8 秒，但 APScheduler 对普通任务默认只允许约 1 秒的迟到时间。插件较多或容器更新后启动较慢时，调度器真正启动前任务时间已经过去，初始化任务会被判定为错过并删除。

这会产生以下现象：

- 插件仍显示为启用状态。
- 保存的动态执行时间仍存在，但启动后的状态刷新和过期补跑没有执行。
- 用户打开插件并手动刷新后，动态任务才会重新注册。
- 朱雀助手和签到插件不容易长期卡住，因为它们还保留固定 CRON 任务；四个 Vue 插件主要依赖动态一次性任务，没有相同的固定兜底。

## 目标

- MoviePilot 容器重启或更新后，四个插件的启动初始化必须在调度器可用后执行。
- 即使初始化任务比计划时间晚执行，也不能被 APScheduler 删除。
- 保留现有动态时间计算，不改成固定周期运行。
- 插件启动后发现保存的任务已经过期时，继续沿用现有刷新和补跑判断。
- 避免同一插件的动态任务重复或并发执行。

## 不在本次范围内

- 不调整收菜、搬砖、沙滩、展位、老虎机、舞台和挖角的业务规则。
- 不增加周期性网站请求或固定 CRON 兜底。
- 不修改前端页面和配置项。
- 不触发实际游戏操作作为自动化测试的一部分。

## 方案

### 动态服务保护

四个插件返回动态 `date` 服务时，在传给 MoviePilot 调度器的参数中统一加入：

- `misfire_grace_time=None`：任务迟到后仍允许执行。这里的“迟到”指调度器启动时间晚于任务计划时间。
- `coalesce=True`：同一任务积压多次时只合并执行一次。
- `max_instances=1`：同一动态服务同时最多运行一份，避免重复操作。

这些参数只用于动态一次性服务，不改变农场社交 CRON、表情自动挖角以及其他固定任务。

### 启动流程

1. MoviePilot 加载插件配置。
2. 插件将启动初始化标记为待执行，并登记短延迟的 `date` 服务。
3. MoviePilot 完成全部插件服务登记并启动调度器。
4. 即使计划时间已经过去，调度器仍执行初始化服务。
5. 初始化服务刷新网站状态，并使用现有逻辑判断是否需要立即补跑。
6. 刷新完成后，插件重新登记下一次真实动态任务。

### 正常运行流程

初始化完成后，四个插件仍按现有方式只登记最近的一次动态任务：

- Vue-农场：最近成熟时间及其预刷新时间。
- Vue-魔丸：沙滩冷却或搬砖 CRON 中较早的动作。
- Vue-玩偶：最近可收回或需要补位的展位时间。
- Vue-表情：舞台、老虎机、待处理开包结果等最近时间；挖角服务保持独立。

动态任务执行或刷新后，继续重新计算并登记下一次时间，不引入固定执行周期。

## 错误处理

- 启动初始化访问网站失败时，沿用各插件现有的网络重试和错误次数限制。
- 初始化失败不能导致任务并发堆积。
- 后续重新登记动态任务时继续携带迟到保护，避免 MoviePilot 短暂繁忙造成同类丢任务。
- 日志需要明确区分“启动初始化”“正常动态执行”和“过期补跑”，便于再次排查。

## 测试设计

### 调度时序回归测试

模拟以下场景：

1. 插件先登记启动初始化任务。
2. 测试故意等待到任务计划时间之后。
3. 再启动 APScheduler。
4. 断言初始化任务仍执行一次。

该测试需要先证明没有迟到保护时任务会被丢弃，再证明修复后任务能够执行。

### 四插件服务测试

分别断言四个插件返回的动态一次性服务包含：

- `misfire_grace_time=None`
- `coalesce=True`
- `max_instances=1`

同时断言农场社交任务和表情挖角任务的触发方式没有被改变。

### 现有补跑测试

继续运行现有自动补跑测试，确认：

- 保存的动态时间已过期时会刷新并补跑。
- 未到执行时间时只刷新和重新登记任务。
- 自动开关关闭时不会误执行游戏动作。

## 发布与验证

- 四个插件分别升级一个补丁版本。
- 同步各插件后端版本、`package.json`、`package-lock.json`、根目录 `package.v2.json` 和 `README.md`。
- 运行 Python 编译检查、相关单元测试、JSON 解析检查和 `git diff --check`。
- 推送 `main` 后刷新 MoviePilot 插件市场，更新四个插件。
- 实机验证时只检查启动初始化、任务登记和状态刷新，不主动触发收菜、搬砖、赠送、外展或挖角等游戏操作。

## 风险与控制

- `misfire_grace_time=None` 会允许一次性任务在长时间停机后恢复执行。四个插件启动时首先刷新状态，并由现有逻辑判断是否可执行，因此不会直接盲目执行保存的旧动作。
- `max_instances=1` 只能限制同一服务的并发；插件已有的执行锁和跳过判断继续保留，形成第二层保护。
- 本次不增加高频巡检，避免四个插件产生额外网站访问和日志噪音。
