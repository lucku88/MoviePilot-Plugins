# Vue-魔丸配置代号与双栈访问设计

## 1. 背景

`Vue-魔丸 v0.2.0` 是一次完整重写。旧版 `v0.1.x` 首次升级时需要清理不兼容的配置、历史和调度数据，但后续小版本更新不应重复清理用户设置。

当前配置页还提供“强制 IPv4”开关，后端会安装专用 IPv4 网络适配器。该限制会阻止仅能通过 IPv6 访问的环境正常连接。

## 2. 目标

- 保留 `v0.1.x` 首次进入 `v0.2.0` 时的一次性重置。
- 首次热更新时不直接清理数据；先要求重启 MoviePilot，重启后再完成最终重置，避免旧版在途任务晚写回。
- 已完成 `v0.2.0` 迁移的用户，后续小版本更新保留配置、历史和调度数据。
- 将“是否需要清理配置”与普通插件版本号分离，只有明确的大改才允许再次清理。
- 删除“强制 IPv4”配置及专用网络适配器，让系统自动选择 IPv4 或 IPv6。
- 本次修改仍使用版本号 `v0.2.0`，不更新市场版本。

## 3. 配置代号

### 3.1 独立代号

后端新增独立的配置代号，例如 `CONFIG_GENERATION = 2`。该数字不随 `v0.2.1`、`v0.2.2` 等普通版本更新变化。

只有以后发生配置结构完全不兼容的大改时，开发者才手工提升配置代号。普通功能修复、页面调整和小版本发布不得提升该代号。

### 3.2 升级判断

插件初始化按以下顺序处理：

1. 已保存的配置代号等于当前代号：直接读取原配置，不清理任何用户数据。
2. 存在旧的 `v020_initialized = true` 标记，但没有配置代号：视为已经完成第 2 代迁移，只补写配置代号，不重置配置、历史或调度。
3. 没有配置代号，也没有旧迁移标记，但 MoviePilot 传入了旧版配置或存在旧运行数据：视为从 `v0.1.x` 首次升级。当前进程只写入安全默认配置和“等待重启”标记，保持插件关闭，不清理历史和计划，也不写入第 2 代代号。
4. 全新安装且没有旧配置：写入安全默认配置和第 2 代代号，不把它记录为一次升级清理。
5. MoviePilot 重启后，进程标识发生变化；插件识别到旧进程留下的“等待重启”标记，执行最终重置，成功写入默认配置后保存第 2 代代号并清除等待标记。
6. 已保存的配置代号与当前代号不同：执行一次大版本重置，成功写入默认配置后再保存新代号。未来版本已经具备停止排空保护，因此不需要重复使用旧版专用的重启门。

配置代号必须在默认配置写入成功后保存。写入失败时保留旧代号，下一次初始化可以安全重试。

### 3.3 首次升级重启门

旧 `v0.1.x` 代码已经加载到内存后，不会自动获得 `v0.2.0` 新增的停止屏障。为了避免旧任务在新插件重置完成后又写回历史或动态计划，首次升级采用两阶段流程：

1. `v0.2.0` 第一次在旧 MoviePilot 进程中加载时，为当前进程生成稳定标识并保存到插件数据。
2. 插件写入安全默认配置、保持停用，并在配置页显示“请重启 MoviePilot 完成升级”的条件提示。
3. 同一进程内再次初始化、保存配置或尝试启用时仍保持等待状态，不注册自动任务。
4. MoviePilot 重启后会生成新的进程标识；插件确认进程已经更换，再清理旧配置、历史、状态缓存和动态调度计划，最后写入配置代号 `2`。
5. 完成后不再显示提示，用户可检查设置并手动启用。以后 `v0.2.x` 小更新直接保留数据，不要求重启。

进程标识只用于区分“同一次热更新进程”和“已经完整重启”，不得通过配置 API、日志或前端暴露具体值。

### 3.4 保留范围

同一配置代号内升级时保留以下内容：

- 插件启用状态和全部功能开关。
- Cron、重试、延迟和保留魔丸数量等参数。
- 执行历史、状态缓存和下次运行计划。
- MoviePilot 站点 Cookie 同步方式。

新增配置字段使用代码中的默认值补齐；删除的字段在读取时忽略，并在用户下次保存配置时自然移除。

## 4. IPv4 与 IPv6 访问

### 4.1 配置清理

以下内容全部删除：

- 配置页的“强制 IPv4”开关和说明。
- 前端默认配置、允许字段和校验字段中的 `force_ipv4`。
- 后端默认配置、公开配置、保存配置和实例状态中的 `force_ipv4`。
- 站点客户端构造参数中的 `force_ipv4`。
- `_IPv4HTTPAdapter` 专用适配器。

旧配置中残留的 `force_ipv4` 不报错，只忽略该字段。用户下一次保存配置后，MoviePilot 中保存的公开配置不再包含该字段。

### 4.2 网络行为

站点客户端统一使用 `requests` 的标准 `HTTPAdapter`。域名解析和连接地址由操作系统、DNS、`requests` 与 `urllib3` 正常选择，不再强制绑定 `0.0.0.0`。

结果如下：

- 网络有 IPv4 时可以使用 IPv4。
- 网络有 IPv6 时可以使用 IPv6。
- 同时具备 IPv4 和 IPv6 时，由系统连接策略选择可用地址。
- 代理开关保持原样，仍由 MoviePilot 的代理环境决定是否使用代理。

## 5. 页面与文档

- 基础设置卡片删除“强制 IPv4”，其余开关按现有自适应布局自动重排。
- 删除配置页固定显示的 `v0.2.0` 迁移警告；只在后端明确返回“等待重启”时显示条件提示，完成迁移后自动消失。
- README 改为说明：只有首次从 `v0.1.x` 升级到本次重写会重置，后续小更新保留配置。
- `package.v2.json`、`package.json` 和 `package-lock.json` 继续保持 `0.2.0`。

## 6. 测试

后端测试覆盖：

- 旧 `v0.1.x` 配置首次升级时仍重置一次。
- 已有 `v020_initialized` 标记的用户补写配置代号时保留配置、历史和计划。
- 同一配置代号重复初始化不会清理数据。
- 模拟提升配置代号时只重置一次，写入失败后仍可重试。
- 模拟旧版首次热更新时只进入等待重启状态，不提前清理旧历史和计划，也不写入配置代号。
- 模拟同一进程重复加载时仍拒绝启用；模拟进程标识变化后执行最终重置并清除等待标记。
- 等待重启状态不把内部进程标识暴露给配置 API，配置页禁用保存并显示条件提示。
- 后端公开配置和保存结果不再包含 `force_ipv4`。
- 站点客户端始终使用标准适配器，不修改全局网络行为。

前端与发布测试覆盖：

- 配置源码和正式构建产物中不再出现“强制 IPv4”或 `force_ipv4`。
- 配置页不再显示固定迁移警告。
- 运行干净的 `npm ci` 和正式构建，并核对 `dist` 产物。
- 运行 Python 编译、相关单元测试、JSON 解析和 `git diff --check`。

## 7. 不在本次范围

- 不更改 `Vue-农场`、`Vue-玩偶` 或 `Vue-表情` 的网络配置。
- 不修改搬砖、沙滩、炼造、兑换、赠送和动态调度业务逻辑。
- 不自动安装或更新 MoviePilot 中的插件。
- 不提升 `Vue-魔丸` 市场版本号。
